### Tokens

Les LLM travaillent avec des tokens pas des lettres.

Token est un bout de mot. Les tokens ont été mise en place initialement pour la compression de texte.

Utilisé pour les raisons suivantes :
- Efficacité
- Gestion de la mémoire (utilisation réduite de la mémoire)
- Pour faire des liens entre les tokens (Concept nommé "Attention") => création de matrice entre les tokens (avec des lettres la matrice serait encore plus grande)

Algo pour créer des tokens
- BPE Byte Pair Encoding (GPT)
- ...

Pre tokenization utilisée par certain algo

Regroupement des lettres en token quand des combinaisons sont fréquentes

Composition des mots avec le moins de token possible

Utilisation du caractère _ pour indiquer la présence d'un espace

### Foundation & instruction tuned

Foundation = model de base

Instruction entrainée à partir du model foundation pour répondre aux questions (spécialisation du modèle)

### Condition d'arrêt de la génération des tokens ?

Entrainement à partir de question réponse avec |endoftext| token particulier pour désigner la fin du texte utilisé (condition d'arrêt de la génération de la réponse) pour entraîner le LLM

### Choix du prochain token ?

Utilisation de la matrice + texte précédent + statistique pour trouver le prochain token

Top-K : Ne regarder que les n tokens les plus probables.

Top-P : Ne regarder que les tokens dont la somme est supérieure à une probabilité données

SoftMax : fonction pour convertir des valeurs de [- infini, + infini] entre [0, 1]

Top-K faible => déterministe (température basse)

Top-K haut => plus créatif (temperature haute)

Les LLM ne sont pas réellement déterministes, car les calculs de nombre flottant ont 
des problèmes d'arrondi + GPU ne garantissent pas l'ordre d'exécution (optimisation)
